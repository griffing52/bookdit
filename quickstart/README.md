# Quickstart

Everything here runs on a laptop in seconds, from a clean checkout. It is the fastest way to confirm
an install and to watch the model run. Corpus construction, training BookDiT on LOBSTER data, and
official LOB-Bench generation and scoring are in [`../docs/REPRODUCE.md`](../docs/REPRODUCE.md).

Assumed: `uv sync --frozen --extra dev` has run (see the root [README](../README.md)) — the `dev`
extra supplies pytest. Prefix commands with `uv run --no-sync` if you installed with `uv`.

## What ships here

| | What it is | Origin |
|---|---|---|
| `toy_data/` | four synthetic LOBSTER-format CSVs (two days); format spec in [The toy data](#the-toy-data) below | generated by `make_toy_lobster.py` |
| `make_toy_lobster.py`, `train_toy.py`, `inspect_checkpoint.py` | the three runnable scripts | — |

No model weights ship with this repository. With LOBSTER data you train your own with
`scripts/lib/train_bookdit.py` ([`REPRODUCE.md` §3.3](../docs/REPRODUCE.md#33-train-bookdit)).

## Checking the install

```bash
python -m pytest tests/ -q                                  # the unit suite, seconds
python quickstart/train_toy.py --out-dir runs/quickstart    # pico BookDiT on synthetic books, 2 epochs
```

`train_toy.py` takes the paper's training path at toy size. It reads each toy day's 40 orderbook
columns and message times, maps them to the 41-channel `midspread_dt` coordinate chart
([`scripts/lib/lob_representation.py`](../scripts/lib/lob_representation.py): log spread, mid
increment, log ladder gaps, absolute sizes, log1p(Δt)), standardizes every channel with the
training day's mean and std, and trains the BookDiT backbone at the `pico` size of
[`make_model_family.py`](../scripts/lib/make_model_family.py) (embed 32, depth 1, one head;
31,209 parameters) with the flow-matching loss. It is smaller than the paper in three ways: 100-frame
windows (stride 10) instead of 500, two synthetic days instead of the corpus, and two epochs. It is a
smoke test: the toy days are a random walk on a regular ladder, so only completion is informative.

It streams a progress bar, prints a one-line summary, and writes a config, a metrics file, a
training-curve plot, the trainer's `checkpoints/{best,last}.pt`, and `bookdit_pico.pt` into
`<out-dir>/<run-name>/` (default `runs/quickstart/toy_smoke/`). `bookdit_pico.pt` carries the keys
of a `train_bookdit.py` checkpoint that the inspector and scorers read.

## Reading a checkpoint

`inspect_checkpoint.py` takes the path of a checkpoint (the toy one above, or one you trained) and
prints its metadata:

```bash
python quickstart/inspect_checkpoint.py runs/quickstart/toy_smoke/bookdit_pico.pt
```

```
runs/quickstart/toy_smoke/bookdit_pico.pt  (131 KB)
keys: ['arch', 'flop_budget', 'mean', 'model_state_dict', 'n_enc', 'rep', 'seed', 'seq_len', 'size', 'std', 'steps']

  arch: 'bookdit'
  flop_budget: 5280562800.0
  mean: tensor(41,)  dtype=torch.float32
  n_enc: 31209
  rep: 'midspread_dt'
  seed: 42
  seq_len: 100
  size: 'pico'
  std: tensor(41,)  dtype=torch.float32
  steps: 36

  model_state_dict: 27 tensors, 31,209 parameters total
```

The per-channel normalisation statistics (`mean`, `std`), the representation name, the
architecture and the context length travel with the weights, so a scorer needs no config file.
The paper's checkpoint was saved with `arch: 'wandit'`; the model registry resolves it, and
`bookdit`, to the same class. `n_enc` is the total parameter count. `--state-dict` adds every
tensor shape. The file is opened with `torch.load(..., weights_only=True)`.

## The toy data

The four CSVs in `toy_data/` are synthetic: the mid-price is a ±1-tick random walk starting at
$100.00, the levels are a regular 100-unit ladder around it, and sizes are uniform integers. They
carry no real microstructure. `python quickstart/make_toy_lobster.py` regenerates them byte for
byte, needing only numpy — `default_rng(0)` for day 1 and `default_rng(1)` for day 2, 1500 rows
per day.

Two properties of the layout are load-bearing. Filename stems must mark each file as a book or a
message file, which is what `discover_lobster_pairs` keys on (`src/bookdit/data/lobster.py`); and
two days are required, because `split_lobster_pairs` reserves the last pair for validation. The
ticker and dates in the filenames are placeholders; `34200000_57600000` is the LOBSTER
session-window convention (09:30:00–16:00:00 in ms).

The column layout matches a real LOBSTER level-10 export. Orderbook: 40 integer columns,
`[ask_price, ask_size, bid_price, bid_size] × 10` levels, prices in 1/10000 of a dollar.

```
1000200,384,1000000,109,1000300,368,999900,444,...
```

Message: 6 columns, `time, event_type, order_id, size, price, direction`, row-aligned with the
book. `train_toy.py` uses only the first column, the time in seconds after midnight, for the Δt
channel.

```
34216.303656403,3,879363,172,1000200,-1
```
