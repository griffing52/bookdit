> **TL;DR.** BookDiT generates limit order book *states*, not messages, in coordinates where every
> generated frame has a positive spread and monotone price ladders (before tick rounding). Over a 16,000-message rollout on 39
> fixed windows, its L1¹⁸ drift slope is not distinguishable from a real-vs-real control and is 3.4×
> lower than that of a compute-matched LOB-S5 retrain. On the one-shot LOB-Bench evaluation it trails
> that retrain on the full 21-statistic suite (0.249 vs 0.228) and leads on the clock-excluded 18
> statistics (0.193 vs 0.219). These are the numbers of the checkpoint reported in the paper, selected from three
> training seeds on held-out validation days; across six seeds of the same configuration L1¹⁸ is 0.222 ± 0.020 against the
> retrain's 0.218, and drift varies by seed.

## Overview

Code for the ICAIF '26 paper. This is a code-only release: no trained weights, no generated
samples and no result files ship, because all of them are derived from licensed LOBSTER data (see
[Data](#data)). With your own LOBSTER data, the scripts here train the model and regenerate the
tables and figures listed in [`docs/REPRODUCE.md`](docs/REPRODUCE.md).

BookDiT is a 0.95 M-parameter flow-matching diffusion transformer. Each token is one ten-level book
state, taken after every tenth message, and the model denoises whole blocks of future states at once.
States are predicted in a **structured chart** (log spread, mid increment, log level-to-level gaps,
absolute sizes, log1p elapsed time), so the price coordinates of every generated frame give a positive
spread and a monotone ladder by construction (the IDM decoder then rounds prices to the tick, after
which a small fraction of frames can be locked or have tied levels); sizes are not constrained this way and are clipped at
zero when decoded. An inverse-dynamics (IDM) decoder turns generated states back into LOBSTER
messages, so BookDiT can be scored on LOB-Bench next to message models.

Where each idea lives:

**Reported checkpoint.** The paper's numbers come from one checkpoint (953,769 parameters, `mini`
size, seed 1, 109,216 steps × batch 32 × 500 states, 1e16-FLOP budget), selected from three training
seeds by LOB-Bench L1 on two held-out GOOG validation days.

The rows come from separate scoring runs on different window sets (*n*), so compare across rows with
care; [`docs/PROTOCOL.md` §7](docs/PROTOCOL.md#7-window-counts) says which rows share a set.

- **Same window set.** On the 3,111 windows that BookDiT, the LOB-S5 retrain, the three
  data-matched seeds and the six seeds below all keep, `bookdit_refine` scores 0.250 / 0.193 / 0.187 and `lobs5_retrain`
  0.228 / 0.218 / 0.215.
- **Data-matched.** BookDiT trained on the six GOOG days the LOB-S5 retrain was trained on, at the
  same compute; the row is the mean of three seeds, and the paper's
  L1¹⁸ = 0.180 ± 0.010 is that mean with the seeds' sample standard deviation.
- **Refinement rows.** "+ refinement" and "without refinement" are the same checkpoint, generation
  settings and decoder; both apply the 50-share resting-size deadband before decoding, in the
  decoder's quantized price space. They differ only in the deep-level median filter (`--refine`),
  which lowers L1²¹ 0.256 → 0.249 and L1¹⁸ 0.201 → 0.193 and raises book-10 0.177 → 0.187
  ([`docs/PROTOCOL.md` §4](docs/PROTOCOL.md#4-the-idm-decoder)).
- § The camera-ready Table 1 prints these values. The submitted version printed 0.259 / 0.204 /
  0.179, an unrefined generation decoded with the decoder's built-in band on raw size columns, so
  it differed from the refined row in where the deadband acts as well as in the median.
- **Decoded horizon.** BookDiT generates 50 states (500 messages of event time); every message the
  decoder emits for those states is scored, which is not a fixed 500-message count ([`docs/PROTOCOL.md`
  §3](docs/PROTOCOL.md#3-the-conditioning-arithmetic)).
- † The released RWKV samples use per-day window indexing and share 582 windows with the other
  systems. On those 582 windows BookDiT + refinement scores L1²¹ 0.275 and L1¹⁸ 0.216.
- ‡ Our reproduction. Painting's message timestamps come from the evaluation harness (uniform over
  the real window's span), not from the model, so L1²¹ is not reported; the file's `l1_21` value
  includes the three clock statistics computed on those interpolated timestamps. 847 of its 3,136
  windows survive the level-ten filter and 844 are shared with BookDiT.

### Long-horizon drift (paper §5, Figure 2 right, Figure 3)

On 39 windows held identical across all 32 blocks of a 16,000-message rollout, the L1¹⁸ slopes in
10⁻³ per 1,000 generated messages are 1.14 [−0.12, 2.55] for BookDiT, 3.84 [1.91, 5.41] for the
compute-matched LOB-S5, 1.05 [0.06, 2.48] for CST and −0.05 [−0.48, 0.61] for a real-vs-real control;
LOB-S5 − BookDiT = +2.70 [+0.49, +4.48], p = 0.006. Under LOB-Bench's
divergence protocol on 900 windows (H = 100), the released LOB-S5's control-adjusted divergence
slope is 3.12× BookDiT's (3.08× at H = 50).

## Install

```bash
uv venv
uv sync --frozen --extra dev   # exact locked versions plus pytest
```

A plain `python -m venv .venv && .venv/bin/pip install -e ".[dev]"` also works, at floating
versions. Python 3.11 or newer. Prefix commands with `uv run --no-sync` if you installed with `uv`.

The LOB-Bench scoring scripts (everything under `scripts/` that scores or decodes against LOB-Bench,
e.g. `score_official.py`, `apply_deadband.py`, `cst_prep.py`) need the pinned LOB-Bench clone and
exit with a pointer to it, even for `--help`, until it exists. Run `bash scripts/data/setup_libs.sh`
once before using them. The quickstart and the tests do not need it.

## Data

Corpus construction, training and the official LOB-Bench
scoring need your own LOBSTER subscription (<https://lobsterdata.com>); see
[`docs/REPRODUCE.md` §1.1](docs/REPRODUCE.md#11-data-layout). The only market-format data shipped
is the synthetic toy set in `quickstart/toy_data/`.

**Required input format.** The corpus and the evaluation reference are built by replaying each
ticker-day's message file through a matching engine, starting from an empty book. That only works
with **full-depth** message files (every price level) that cover the **whole session from the
04:00 pre-market open**, one file per ticker-day, as exported by an institutional LOBSTER server.
The files use the LOBSTER message columns (time, type, order id, size, price, direction). The
files we used carry an extra trailing seventh column, which the loader ignores: it reads only
time, type, size, price and direction. Rows of type 5 (hidden execution), 6 (cross) and 7 (halt)
leave the visible book unchanged. A standard LOBSTER download (09:30–16:00, level *N*) does not
work. It carries only events inside the requested levels and none before the open, so orders that
rest deeper or were entered pre-market have no submission message, and the replay drifts from the
true book. On two standard level-10 days we checked, the replay matched LOBSTER's own orderbook
file on 0.45% and 0.10% of rows. Run `scripts/lib/reconstruct_event_book.py --validate` on one day
of your data before a full build. It needs a matching LOBSTER orderbook file for that day.

## What runs from a checkout

Without any data, on CPU, in seconds ([`quickstart/README.md`](quickstart/README.md)):

- the unit tests (`python -m pytest tests/ -q`);
- a pico-size BookDiT training run on two synthetic LOBSTER-format days in the paper's 41-channel
  representation (`python quickstart/train_toy.py`), a smoke test of the training path;
- the checkpoint inspector on that run's output (`python quickstart/inspect_checkpoint.py
  runs/quickstart/toy_smoke/bookdit_pico.pt`), which reads the file without building a model.

Training on real data, generation, decoding and LOB-Bench scoring all need LOBSTER data and are
in [`docs/REPRODUCE.md`](docs/REPRODUCE.md), which lists the commands behind each paper table and figure.

```

                      used by the tests (the quickstart uses the backbone and trainer)

                      conditional prediction
```
